# A 19-state twin-prime beeper

`machines/twinprime_native.txt`: a 2-symbol Turing machine with a designated **beep state**. Started on the
blank tape, it never halts and enters the beep state exactly once for every lesser twin prime `p ≥ 3`
(`p` and `p + 2` prime), in increasing order: 3, 5, 11, 17, 29, 41, 59, 71, 101, … So it **quasihalts iff
there are only finitely many twin primes**. It replaces the 265-state counter-machine compile
(`machines/twinprime.txt`).

Standard text (bbchallenge format, `A` = start, `---` = never used), beep state **F**:

    1RB1LA_1RC0RD_1LA1RC_---0RE_0LF0LH_0LO---_0LN0LH_0LI1LH_1RJ1LI_0LK0RL_0RJ1LK_0RM1RL_1RG1RM_0LO1LN_1RC1LP_1RS1LQ_1RC1LR_1RS1LR_0RD1RS

## How it compares

The best known machine for this conjecture is the 18-state machine of C. Reams
([calr3/tinycryptids](https://github.com/calr3/tinycryptids/tree/main/twinprimes), Oct 2026, proved in Lean).
It marks a beep **transition** (one table entry), not a beep state. Our convention (`ZP.Quasihalts`, Aaronson's
Beeping Busy Beaver) needs a state entered only at beeps, which costs one state: here state `BP`, entered only
from `G2` reading 0. Counted the same way the two machines tie: drop `BP` and make `G2`'s 0-transition
(`0 L V`) the beep transition, and this design has 18 states. The algorithm is the same family as Reams'
(trial division with a hole counter mod `d`, one walk testing `m` and `m + 2`, scanners that count zeros,
and a shift in which the separator becomes `D`'s next hole). The differences: `R`'s hole moves right, the walk
ends with a scan back (`V`) instead of a scan forward after the shift, the start reuses the rebuild with an
otherwise unused transition (`C5` reading 0), and the beep path goes straight into the check. No two states
of this design are compatible, so state merging gives nothing.

## Design (`design.py`)

Tape, blank elsewhere:

    D 0 R

* **D**: `d` cells, all 1 except one **hole** (0) at cell `c`, a counter mod `d`.
* **0**: the separator.
* **R**: `r = m − d` cells of 1; during the walk one hole moves right through it.

Candidate `m ≥ 3`, divisor `d = 2, …, m − 1`. For `m ≥ 3`: `m` and `m + 2` are both prime iff no `d` with
`2 ≤ d < m` divides `m` or `m + 2`.

| phase | states | what it does |
|---|---|---|
| walk start | `G2` | on R's first cell: 1 = make it R's hole (as `B`); 0 = R is empty: **beep** (`BP`) |
| walk | `B Y1 Y2 A W Z1 Z2` | `r` times: make the next R cell the R hole (`B`), scan left past the separator to D's hole (`Y1`, `Y2`), fill it and make the next cell the hole (`A`; at the separator wrap to cell 0 with `W`), scan right past the separator to R's hole (`Z1`, `Z2`), fill it. D's hole starts on its last cell, so it ends on `c = (d − 1 + r) mod d = (m − 1) mod d`. |
| check | `V X1 X2 X3 H0` | back to the separator (`V`), then read D's cells `d−1`, `d−2`, `d−3`: the hole on `d − 1` means `d ∣ m`, on `d − 3` means `d ∣ m + 2` (FAIL); on `d − 2` or further left (`H0` fills it) `d` passed |
| shift | `H1 G1` | to the separator, which stays 0 and becomes D's new last cell (the next hole); R's cell 0 becomes the separator (`d += 1`, `r −= 1`); then `G2` |
| beep | `BP` | entered only from `G2` on 0 (`d = m`, every `d` passed); goes to `X1`, which sees the hole on `d − 1` (`m ∣ m`) and FAILs |
| rebuild | `C1 C4 C5` | FAIL: fill the hole and the separator (`C1`), add a 1 at the left end (`C4`), write the hole (`C5`) and the separator (`G1`): `D = 1 0`, candidate `m + 1` |
| start | `C4` (state 0) | on the blank tape `C4`, `C5` (its 0-transition, used only here) and `C1` build `1 1 1 1`, and the rebuild makes `1 0 0 1`: `m = 3`, `d = 2` |

Round invariant (what the Lean proof formalizes): every entry to `G2` sees the tape `1^(d−1) 0 0 1^(m−d)` with the
head on cell `d + 1`, for the `(m, d)` of trial division in order.

## Checks

* `python3 twin/test_twin.py`: the machine files are what `export.py` writes; every `G2` entry for `m < 90`
  (365 rounds) has exactly the tape above; `BP` is entered exactly at the lesser twin primes.
* `gcc -O2 -o twsim twin/twsim.c && ./twsim machines/twinprime_native.tbl 3000000000 40`: 34 beeps, at the first 34
  lesser twin primes (3 … 857), within 2.7·10⁹ steps.
* Lean: `formal/ZP/TableTwin.lean` (generated by `formal/gen_table.py twinprime_native`); the proof is plan 09.
