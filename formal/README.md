# Formal verification (Lean 4, Palomar layout)

This directory is a self-contained Lake project. It uses **core Lean only, no
Mathlib**: a clean CI build takes about a minute instead of the usual Mathlib
cache download and build. The layout follows the
[Palomar](https://palomar-registry.org/) template:

| file | role |
|---|---|
| `Challenge.lean` | the advertised statements (one deliberate `sorry` each) |
| `Solution.lean` | the same declaration, proved from the development |
| `Challenge.lean`, `ZP/AllDefs.lean` | generated by `gen_challenge.py` from the trusted sources below (`ZP/Defs*.lean`, `ZP/Table*.lean`, which nothing imports): the Challenge is one self-contained module over Lean core, as Palomar compiles it alone; `ZP.AllDefs` is the same definition block as a project module so the development elaborates it identically |
| `ZP/Defs.lean` | **trusted surface**: TMs, quasihalting, guest semantics (`ref/zp2_ref.py`), the Σ₂ sentence |
| `ZP/Table.lean` | the literal 278-state table, generated from `machines/zp_native.tbl` by `gen_table.py` |
| `ZP/Abstract.lean` | L4: the abstract program quasihalts ⟺ `Sentence` (**proved**) |
| `ZP/Bridge.lean` | macro simulation ⟹ same quasihalting (**proved**) |
| `ZP/LTM.lean` | 4-symbol logical machines and their macro simulations |
| `ZP/Logic.lean` | the 129-state logical machine `native/zp2.py` and the compilation certificate, generated by `gen_logic.py` |
| `ZP/Zip.lean` | logical machines on stream tapes, linked to `LTM.conf` (**proved**) |
| `ZP/Rot.lean`, `ZP/Fuel.lean`, `ZP/Interp.lean`, `ZP/Run.lean` | N3: code rotation, fuel odometer, one guest step, the whole guest run (**proved**) |
| `ZP/Pair.lean` | N3: one pair of the outer loop, `pair_main` (**proved**, segments checked by `decide +kernel`) |
| `ZP/Logical.lean` | N3: the logical machine simulates the abstract program, from `pair_step` (**proved**) |
| `ZP/Compile.lean` | N1+N2: the table simulates the logical machine (**proved**, gadgets checked by `decide +kernel`) |
| `ZP/Complexity.lean` | one-tape TMs (`Mach`, `exec`), `InP`, `InNP`, `PeqNP`; P ⊆ NP (**proved**) |
| `ZP/GuestTM.lean`, `ZP/GuestCompile.lean` | a guest code is a TM and every TM is a guest code of any padded length, step for step (**proved**) |
| `ZP/PNP.lean` | `Sentence` ↔ some guest decides L within its clock; L ∈ P → `Sentence`; P = NP ∧ L ∈ NP → `Sentence` (**proved**) |
| `ZP/Zx.lean`, `ZP/Gad.lean`, `ZP/Pop.lean`, `ZP/Prog.lean`, `ZP/Lib.lean` | machine toolkit: zipper semantics, tape gadgets, a stack language compiled to machines (**proved**) |
| `ZP/Sim.lean`, `ZP/UG.lean`, `ZP/Verif.lean` | a stack program that simulates any `Mach`; the universal guest interpreter; **L ∈ NP** (`Lp_InNP`) |
| `ZP/Clock.lean`, `ZP/Raw.lean`, `ZP/Decide.lean` | clocks, P ⊆ NP (`InP_InNP`), and **`Sentence → L ∈ P`** (`InP_of_Sentence`) by a clocked simulation of the guest decider |
| `ZP/Body.lean`, `ZP/Scan.lean`, `ZP/Dx.lean` | the instance machine `DX V k m x` of an NP verifier: input check, certificate bound, clocked run of `V` |
| `ZP/Tg.lean`, `ZP/Ents.lean`, `ZP/Gen.lean`, `ZP/Gx.lean` | the compiled code of `DX V k m x`, written out by a stack program `GEN` in polynomial time |
| `ZP/HardB.lean`, `ZP/Hard.lean` | polynomial bounds; **L is NP-hard** (`red_iff`, `InP_of_InNP`) and **`Sentence ↔ P = NP`** (`sentence_iff_PeqNP`) |
| `ZP/Checks.lean` | kernel-evaluated (`decide`) agreement with `ref/zp2_ref.py` on small cases |
| `comparator.json`, `formalization.yaml`, `LICENSE` | Palomar submission metadata |

The advertised theorem:

```lean
theorem ZP.zp_quasihalts_iff_sentence : ZP.Quasihalts ZP.zpMachine ↔ ZP.Sentence
```

The machine is Z_P v2, the 278-state native design (`docs/native.md`); until
2026-11 the development targeted the 1371-state v1 table.

`Sentence ↔ P = NP` is **proved** as well (`ZP/Hard.lean`):

```lean
theorem ZP.Cx.sentence_iff_PeqNP : ZP.Sentence ↔ ZP.Cx.PeqNP
```

* `P = NP → Sentence`: L ∈ NP (`Lp_InNP`) and L ∈ P → `Sentence` (`ZP/PNP.lean`).
* `Sentence → P = NP`: P ⊆ NP (`InP_InNP`); `Sentence` gives a machine deciding L in
  polynomial time (`InP_of_Sentence`); every NP language reduces to L by
  `x ↦ code (DX V k m x) ((|x|+2)^E)`, computed by the stack program `GEN` in
  polynomial time (`red_iff`, `gen_ok`), so it is in P (`InP_of_InNP`).

## Status
* CI (`.github/workflows/ci.yml`, job *Lean*) builds everything and prints a census of the
  open `sorry`s. It also checks that `ZP/Table.lean` matches the current `machines/zp_native.tbl` and that
  `ZP/Logic.lean` matches `native/zp2.py` and the build (`gen_logic.py`).
* The *Comparator* job runs `lake comparator` as Palomar does. It is marked
  required. The development has no `sorry` left (it passes), so the repository
  can be submitted at <https://submit.palomar-registry.org/> with config path
  `formal/comparator.json`.

## Local use
In a cloud session, install the toolchain from GitHub as in `plans/00-setup.md` (elan's own
download host is blocked by the proxy). Plans for the other native machines are in `plans/`.
```bash
cd formal && lake build                 # needs elan; toolchain from lean-toolchain
./scripts/verify-comparator.sh          # needs bwrap
python3 gen_table.py                    # after python3 build.py changed machines/zp_native.tbl
python3 gen_logic.py                    # likewise, for the logical machine and certificate
```

## The bridge
`ZP/Bridge.lean` reduces the bridge to one structure, `MacroSim zpMachine`: strictly
increasing times `time n`, one per abstract step, such that the table visits its beep
state in `[time n, time (n+1))` iff `absState n` is a refutation. The transfer of
quasihalting from such a simulation is proved.

`ZP/Compile.lean` proves that a macro simulation by the 4-symbol logical machine
(`LMacroSim zpLogic`, which also says the logical machine never halts) gives one by the
table. Each logical transition is carried out by a gadget of at most 5 table steps on
the pair encoding `B=00 M=01 0=10 1=11`. `wRun_sound` shows that a run on a 6-cell
window is a run on every tape that agrees with it, and `chk0`…`chk4` evaluate every
gadget, for all 4 symbols and all 16 values of the neighbouring cells, in the kernel:
right target state, head and window, no visit to the beep state on the way. This covers
layers N1 (state merging) and N2 (pair compilation) at once, without trusting the
compiler: `gen_logic.py` only supplies the certificate (entry state, entry cell and
gadget length per logical state and symbol).

| Layer | Statement | Status |
|---|---|---|
| N0 table | `ZP/Table.lean` is `machines/zp_native.txt` | CI regenerates and diffs it |
| N1+N2 compile | the table simulates the 129-state logical machine `native/zp2.py` gadget by gadget | **proved** (`ZP/Compile.lean`) |
| N3 logical machine | from the layout `M_g J M_1 s M_2 C M_3 M B_R … M B_1` of pair `(J, s)` the logical machine reaches the layout of `absStep (J, s)`, beeping once iff `J` is wrong on `s`, and never meets an undefined transition | **proved**: `ZP/Logical.lean` derives the whole simulation from `pair_step` (from `lay J S` the machine reaches `lay` of `absStep (J, S)`, visiting the beep state iff `J` is wrong on `S`), proved in `ZP/Pair.lean`: one guest step = the rotation walk; fuel odometer = clock `(|s|+2)^(|J|+1)-1`; certificate countdown = `inL`; outer loop = `absStep` |
| N4 abstract ⟺ `Sentence` | | **proved** (`ZP/Abstract.lean`) |

Certificates must be checked by `decide` or `rfl` in the kernel. `native_decide` adds
the axiom `Lean.ofReduceBool`, which Palomar does not permit.
